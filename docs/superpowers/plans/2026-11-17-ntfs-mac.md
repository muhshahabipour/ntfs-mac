# NTFS for Mac — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS menu bar app that auto-detects NTFS disks and mounts them read/write via ntfs-3g, handles Windows "dirty" disks safely, and looks like the reference design.

**Architecture:** SwiftUI `MenuBarExtra` app → XPC → root launch daemon (`SMAppService`) that runs `ntfs-3g` over macFUSE. Pure logic (health classification, mount command building, card-state reducer, speed smoothing) lives in a testable `NTFSCore` library behind small protocols (`ProcessRunning`, `DiskEventSource`) so tests never touch a real disk.

**Tech Stack:** Swift 6.4, SwiftUI, DiskArbitration, IOKit, XPC, `SMAppService`, Swift Testing, macFUSE, ntfs-3g (Homebrew).

**Spec:** `docs/superpowers/specs/2026-11-17-ntfs-mac-design.md`. UI reference images: `docs/design/ui-dark.webp`, `docs/design/ui-light.webp`.

## Global Constraints

- Target: macOS 27, Apple Silicon (arm64) only. Personal use, no notarization, no auto-update.
- UI is Persian, fully right-to-left, Persian digits (۰-۹), light/dark/auto theme selector, matching the reference images.
- Never write to or repair a dirty/hibernated volume without explicit per-action user consent in the UI.
- Eject always does a clean unmount first; if busy, say which process holds the volume.
- Tests run only against virtual NTFS disk images, never a real drive.
- Copy progress: show live disk throughput only. No pause button, no file counts, no ETA (Finder does the copy).
- Paragon's `ufsd_NTFS.fs` present on the machine: detect it, explain, and act only with consent.

## Review Focus

- Volume label with spaces, Persian letters, quotes or `/` → mount point and command args must not break or be injectable (Task 4).
- Volume both hibernated and dirty, or `ntfsfix` fails → show "needs Windows", never offer a destructive force mount (Task 2).
- Disk yanked mid-copy/mid-mount → card disappears cleanly, no crash, no stale mount point left (Tasks 3, 4, 8).
- Two NTFS disks with the same label, or an unlabeled disk → distinct mount points and names (Task 4).
- Full disk (100%) or empty (0%) and >2 TB sizes → ring and Persian size text render correctly (Tasks 8, 9).

## Deviations discovered while building (2026-11-17)

- Task 2: `classifyHealth(probeStatus:)` uses only the exit code (documented in the `ntfs-3g.probe` man page); `probeStderr` dropped. Added `VolumeHealth.inUse` (exit 16: another driver such as Paragon holds the disk) and `.unknown`.
- Task 3: `ntfsDisk(from:)` also skips internal drives; whole-disk images without a volume kind are not detected (verified manually in Task 10).
- Task 4: added `MountError.extensionNotEnabled`; extra mount options (`noatime`, `windows_names`, `big_writes`) intentionally not enabled until measured.
- Task 7: `isActive(bytesPerSecond:)` became `ActivityDetector` (stateful, 2 s hold-off). `IOKitCounterSource` verified against the built-in disk.
- Task 8: pure `cardState` / `usedFraction` done in `NTFSCore`; `DiskListViewModel` (app target) comes with Tasks 5 and 9.
- Task 1/6: `ntfs-3g` comes from `gromgit/fuse/ntfs-3g-mac`, not Homebrew core.
